# Аршин · Генератор XML

Настольная программа Windows для подготовки пакетных XML с результатами поверки термопреобразователей сопротивления. Приложение читает сохранённые Excel-книги, разворачивает партии, показывает данные и их происхождение, собирает подтверждённые записи и проверяет пакет по приложенной XSD. Файл передаёт в личный кабинет уполномоченный сотрудник.

## Готовые сборки

| Сборка | Файл | Данные |
|---|---|---|
| Portable для Windows x64 | `release\ArshinGenerator-Portable-x64.zip` | `data` рядом с EXE. Переносится вместе с распакованной папкой |
| Установщик для Windows x64 | `release\ArshinGenerator-Setup-x64.exe` | `%LOCALAPPDATA%\ArshinGenerator`. Установка для текущего пользователя, ярлык «Пуск», по выбору ярлык рабочего стола |

Для portable распакуйте архив целиком и запустите `ArshinGenerator.exe`. Для установки запустите установщик и завершите мастер. Приложение поставляется с собственной средой выполнения. Целевая платформа Windows 10 версии 1809 и новее, Windows 11 x64. [Краткая инструкция](docs/quick_start.md) · [Поддерживаемые версии Windows в Qt 6.8](https://doc.qt.io/qt-6.8/windows.html#supported-configurations).

## Рабочий процесс

- Поддерживается версия RTD v1 из комплекта. Читаются сохранённые значения и структура, включая книги с макросами. Исходный протокол открывается только на чтение и макросы не выполняются.
- Двойное нажатие по строке открывает сведения партии: тип и модификацию, дату, методику, заводские номера, результаты, сроки и номера ФИФ ОЕИ. Программа определяет результат по согласованным данным отчёта и измерений. Для приборов с двумя ЧЭ применяется предусмотренное описанием типа число записей.
- Программа сначала проверяет сведения Excel. Сохраните исправленную книгу и добавьте её повторно, чтобы обновить строку. Реквизиты лаборатории применяются к пустым полям. При совпадении условий подтверждённое правило МПИ пересчитывает срок с учётом даты поверки и сообщает о расхождении со старой записью SQLite.
- После проверки Excel MIT, MIETA и VRI сверяют тип и средства поверки на дату протокола. Однозначная карточка применяется автоматически. Среди неоднозначных карточек эталона можно выбрать несколько фактически использованных записей. Выбор сохраняется в SQLite и перепроверяется по реестру. Недоступность реестра блокирует выгрузку.
- Сохранённые реквизиты привязаны к номеру, дате, типу СИ и, для индивидуальных полей, заводскому номеру. Изменения источника перепроверяются для соответствующего поля. Для переноса подтверждений из 1.0.x откройте исходную версию книги с прежней контрольной суммой.
- Кнопка «Сформировать XML» создаёт и проверяет пакет по оригинальной XSD от 19.06.2020. Владелец обязателен. Номер наклейки переносится, если он указан и относится к конкретному СИ. Пользователь подтвердил загрузку пакета без наклеек в рабочую область «Аршина» и автоматическое создание заявки. Окончательная публикация ещё требует проверки. [Схема и поведение портала](docs/schema_discrepancies.md).
- Когда проверены все загруженные протоколы, выберите имя XML в системном окне Windows. Для пакета из нескольких файлов выберите папку. Ненужный протокол можно убрать из списка клавишей Delete. При повторном формировании программа предупреждает о дубликатах. История хранит фактические пути, источники, версию правил и SHA-256 схемы.
- Локальная эксплуатация рассчитана на одно рабочее место. SQLite, подтверждения и диагностический журнал находятся в папке данных. Перенос и резервное копирование описаны в краткой инструкции.

## Сборка и тестирование

Нужны Windows x64, Python 3.12 x64 и Inno Setup 6.7.3. Сборка использует фиксированные версии зависимостей. При отсутствии `python` в PATH передайте абсолютный путь к Python 3.12 через `-Python`.

```powershell
.\build.ps1 -IsccPath 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
.\.venv\Scripts\python.exe -m unittest -v
```

Для пересборки только архива используйте `-PortableOnly`. Для работы из исходников после установки зависимостей используйте `.\.venv\Scripts\python.exe -m arshin_generator`. Ключ `-UseExistingEnvironment` предназначен для уже подготовленной среды с теми же версиями.

Сценарий `./packaging/test-release.ps1` проверяет запуск и перенос распакованного архива. В профиле без установленной программы ключ `-TestInstaller` проводит временную установку с проверкой ярлыков и последующим удалением. Ключ `-CheckConnection` запускает из выбранной сборки контрольные запросы к MIT, MIETA и VRI. [Отчёт проверки сборок](docs/release_verification.md).

## Компоненты

- `readers` определяет вид и версию по структуре книги и возвращает общую модель с источниками. Новый обработчик подключается через `READERS`.
- `domain.py`, `normalization.py`, `validation.py` отвечают за модель, форматирование и сохранённые доказательства пригодности.
- `registry.py`, `public_registry.py`, `http_transport.py`, `storage.py` отвечают за локальный справочник, публичный поиск через WinHTTP на Windows и SQLite.
- `arshin.py` формирует, делит, проверяет и перечитывает XML. Он не использует координаты Excel. Путь XSD задаётся в `Schema`. При замене версии проверить `SCHEMA_FILE`, ресурсы сборки и сценарии обязательных полей. Схема с изменённой структурой может требовать изменений сериализации и проверок.
- `ui` содержит русскоязычный интерфейс. Таблицы обрабатывают общую модель результатов.
