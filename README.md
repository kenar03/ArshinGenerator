# СИ-Экспорт

Настольная программа Windows для подготовки пакетных XML с результатами поверки термопреобразователей сопротивления для ФГИС «Аршин». Приложение читает сохранённые Excel-книги, разворачивает партии, показывает данные и их происхождение, собирает подтверждённые записи и проверяет пакет по приложенной XSD. Файл передаёт в личный кабинет уполномоченный сотрудник.

## Готовые сборки

| Сборка | Файл | Данные |
|---|---|---|
| Portable для Windows x64 | `release\SI-Export-Portable-x64.zip` | `data` рядом с EXE. Переносится вместе с распакованной папкой |
| Установщик для Windows x64 | `release\SI-Export-Setup-x64.exe` | `%LOCALAPPDATA%\ArshinGenerator`. Установка для текущего пользователя, ярлык «Пуск», по выбору ярлык рабочего стола |

Для Portable распакуйте архив целиком и запустите `SI-Export.exe`. При обновлении установленной версии закройте программу и запустите новый установщик. Прежняя база откроется из того же каталога. Для обновления Portable перенесите папку `data` в новую распакованную сборку. Приложение поставляется с собственной средой выполнения. Целевая платформа Windows 10 версии 1809 и новее, Windows 11 x64. [Краткая инструкция](docs/quick_start.md) · [Поддерживаемые версии Windows в Qt 6.8](https://doc.qt.io/qt-6.8/windows.html#supported-configurations).

## Рабочий процесс

- Поддерживаются оба шаблона ТСП/ТСМ. Если в `Оборудование!F1` есть заголовок «Используется», в проверку и XML идут строки со знаком `+` в `F2:F301`. Старые книги используют `Таблицы!A10:A18`. Исходные книги читаются в режиме только для чтения.
- Двойное нажатие по строке открывает подробности и диагностику. Кнопка «Открыть в Excel» рядом с «Закрыть» открывает исходный файл выбранного протокола. Для ТСП/ТСМ предпросмотр показывает регистрационный номер, тип, заполненные исполнение и взрывозащиту. Модификация собирается из `Таблицы!A27:C27`. Каждому физическому прибору соответствует одна запись XML. Результаты всех ЧЭ сверяются с сохранёнными допусками и заключением.
- Программа сначала проверяет Excel. После исправления сохраните книгу и нажмите «Перепроверить». Тип поверки берётся из `Таблицы!B1`. Для ТСП/ТСМ срок рассчитывается из даты `B24` и МПИ `K27` как последний день перед годовщиной. Если в целевом году нет 29 февраля для поверки от 29 февраля, расчёт блокируется до уточнения исходных сведений.
- В настройках можно изменить условный шифр знака поверки и использование результатов калибровки. Исходные значения для новой базы — `ВЦЯ` и «Нет».
- После проверки Excel MIT, MIETA и VRI сверяют официальные реквизиты и действительность поверки средств на дату протокола. Если реквизиты требуют уточнения, исправьте их в Excel и нажмите «Перепроверить». Готовность требует действующей подтверждённой сверки.
- Кнопка «Сформировать XML» создаёт и проверяет пакет по оригинальной XSD от 19.06.2020. Владелец обязателен. Номер наклейки переносится, если он указан и относится к конкретному СИ. Пользователь подтвердил загрузку пакета без наклеек в рабочую область «Аршина» и автоматическое создание заявки. Окончательная публикация ещё требует проверки. [Схема и поведение портала](docs/schema_discrepancies.md).
- Отмечайте протоколы галочками для удаления кнопкой «Удалить выбранные» или клавишей Delete. Галочка в заголовке отмечает все строки. XML включает все загруженные протоколы после их проверки. Повтор полного заводского номера среди приборов одного протокола блокирует выгрузку. История хранит пути, исходный протокол каждой строки, версию правил и SHA-256 схемы.
- В разделе «Сохранение XML» по умолчанию выбран ручной режим. Для одного файла программа открывает «Сохранить как», для нескольких предлагает выбрать папку. В автоматическом режиме файлы сохраняются в заданную папку, а занятые имена получают числовой суффикс. Если папка недоступна, можно выбрать другую для текущей выгрузки.
- SQLite с аудитом и диагностический журнал находятся в папке данных. Служебный запуск для истории, резервной копии и диагностики описан в краткой инструкции.

## Кеш реестров

Подтверждённые сверки действуют 24 часа и сохраняются в SQLite между запусками. Ключ типа — регистрационный номер. Ключ средства включает категорию, официальные реквизиты и дату поверки. «Перепроверить» перечитывает книги и повторно использует действующие сверки. Одинаковые запросы объединяются. В настройках «Принудительно обновить данные ФИФ ОЕИ» повторяет все запросы по доступным реквизитам загруженных протоколов и показывает итог. При временном сетевом сбое предыдущие успешные сверки сохраняются в базе, а текущая сессия показывает результат последней попытки. Перед сохранением XML устаревшие сведения проверяются автоматически.

## Сборка и тестирование

Нужны Windows x64, Python 3.12 x64 и Inno Setup 6.7.3. Сборка использует фиксированные версии зависимостей. При отсутствии `python` в PATH передайте абсолютный путь к Python 3.12 через `-Python`.

```powershell
.\build.ps1 -IsccPath 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
.\.venv\Scripts\python.exe -m unittest -v
```

Для пересборки только архива используйте `-PortableOnly`. Для работы из исходников после установки зависимостей используйте `.\.venv\Scripts\python.exe -m arshin_generator`. Ключ `-UseExistingEnvironment` предназначен для уже подготовленной среды с теми же версиями.

Сценарий `./packaging/test-release.ps1` проверяет запуск и перенос распакованного архива. В профиле без установленной программы ключ `-TestInstaller` проводит временную установку с проверкой ярлыков и последующим удалением. Для проверки обновления добавьте `-UpgradeFrom` с путём к установщику 2.1.0 и `-Python` с путём к Python для подготовки тестовой базы. Ключ `-CheckConnection` запускает из выбранной сборки контрольные запросы к MIT, MIETA и VRI. [Отчёт проверки сборок](docs/release_verification.md).

## Компоненты

- Модуль из `READERS` определяет структуру формата через `matches` и заполняет общую модель через `read`. Каждый обработчик задаёт `VERSION`, `DISPLAY_NAME` и свои правила чтения, измерений и срока. Если подходят несколько обработчиков, импорт останавливается с указанием совпавших форматов. Предпросмотр и XML используют значения из общей модели результатов. Обработчик ТПП/ТПР требует реального шаблона.
- `domain.py`, `normalization.py`, `validation.py` отвечают за модель, форматирование и сохранённые доказательства пригодности.
- `registry.py`, `verification.py`, `public_registry.py`, `http_transport.py`, `storage.py` отвечают за сопоставление, кеш, публичный поиск через WinHTTP на Windows и SQLite.
- `arshin.py` формирует, делит, проверяет и перечитывает XML. Он не использует координаты Excel. Путь XSD задаётся в `Schema`. При замене версии проверить `SCHEMA_FILE`, ресурсы сборки и сценарии обязательных полей. Схема с изменённой структурой может требовать изменений сериализации и проверок.
- `ui` содержит русскоязычный интерфейс. Таблицы обрабатывают общую модель результатов.
