# Схема пакетного импорта

23.11.2026 в официальной справке «Аршина» найдена «XSD-схема файла загрузки сведений о результатах поверки СИ», документ 1679280. В ответе на скачивание имя файла `import.2022-12-21.xsd`, SHA-256 `71843c9544546ce2a319f14f8fd645c6d18c080ad73007070815e2a33e2c5911`, совпадает с пользовательской копией. Документ 1702376 с похожим названием относится к заявке на публикацию. Руководство внешнего портала, документ 5063669, совпадает с приложенным PDF и в п. 3.4.1.11 отсылает к скачиваемой XSD. [Официальная справка](https://fgis.gost.ru/fundmetrology/cm/docs) · [Документ 1679280](https://fgis.gost.ru/fundmetrology/cm/docs/1679280) · [Руководство](https://fgis.gost.ru/fundmetrology/cm/docs/5063669).

Обе исходные схемы имеют пространство имён `urn://fgis-arshin.gost.ru/module-verifications/import/2020-06-19`. Дата в URI одинакова и не определяет версию.

| Отличие | 19.06.2020 | 21.12.2022 |
|---|---|---|
| `applicable/stickerNum` | `0..1`, непустая строка до 128 символов при наличии | `1..1`, шаблон `[0-9]{11}` |
| `miOwner` | `1..1` | `0..1` |
| Идентификатор обычного средства поверки в `means/mis/mi` | Два отдельных необязательных поля `manufactureNum` и `inventoryNum` | Обязательный выбор ровно одного идентификатора |
| `signCipher` | Обязателен, шаблон `[А-Я]{1,3}` | То же |
| `validDate` | `0..1` | `0..1` |

SHA-256 предоставленной схемы 2020 года `cc92b2a1f8670d230a405d42f9ad08a729a6a35cab94751d5bb1208cf493e361`. Публичная справка указывает 2022 для рабочего импорта. Подтверждения приёма XSD 2020 действующим кабинетом нет, поэтому приложение формирует рабочие пакеты по 2022.

| Поле / правило | Руководство v.2.2.4 и снимки | Требование XSD / решение |
|---|---|---|
| `miOwner` | Стр. 97, 1..1 | 0..1, длина 1–512 при наличии |
| `applicable/stickerNum` | Стр. 97, 0..1, строка(128); на снимке пусто | 1..1, ровно 11 цифр ASCII. Положительная запись без номера блокируется |
| `signCipher` | Стр. 97, строка(32) | 1–3 заглавные буквы А–Я |
| `manufactureYear` | Целое число в таблице | `xsd:gYear`. В этом приложении четырёхзначный год |
| `metrologist` | Стр. 97, 0..1 | XSD совпадает. ТЗ требует заполнение и формат Фамилия И.О. |
| `means` | Стр. 46, требуется хотя бы одно поле; метод без средств исключает средства. Стр. 97–99, раздел обязателен | В XSD минимум одна дочерняя ветвь. Для RTD нужен подтверждённый набор средств |
| Свидетельство / извещение | Отдельные видимые поля в ручной форме | В `applicable` и `inapplicable` соответствующих тегов нет |
| Положительная/отрицательная дата окончания | Стр. 97 описывает случаи пропуска при только первичной поверке и непригодности | 0..1. Дата берётся по основанию. При непригодности программа её опускает |
| Размер / обработка | Пп. 3.4.1.11–3.4.1.11.1, PDF 56–57: 5 МБ и целиком отклоняемый файл при ошибке XSD | Проверка UTF-8 по байтам с запасом, проверка всего пакета и повторное чтение с диска |

Приложенный `arshin_export_example.xml` содержит два `result` в правильном namespace. lxml обнаружил пропуск `stickerNum` в обеих записях и пустой `means` во второй. Строки `TechnometerCRMID` говорят о предполагаемом происхождении выгрузки из TechnometerCRM, статус приёма неизвестен. Образцы PDF на стр. 100–108 иллюстрируют ветви единственного СИ, СИ в качестве эталона и разные средства поверки. Они содержат текстовые заполнители, включая «Номер наклейки», и не являются тестовыми файлами для XSD. П. 3.4.7 описывает токены личного кабинета для передачи. Проверка местной схемы не устанавливает правила приёма портала.

Две опубликованные карточки VRI, обычное СИ (`miInfo.singleMI`) и СИ-эталон (`miInfo.etaMI`), содержат `vriInfo.applicable` с `certNum`, `signPass`, `signMi` без `stickerNum`. Ручная форма на приложенном снимке также показывает пустое поле. Источник этих публикаций и серверные правила импорта из публичного ответа не следуют. [VRI, обычное СИ](https://fgis.gost.ru/fundmetrology/eapi/vri/1-495291958) · [VRI, СИ-эталон](https://fgis.gost.ru/fundmetrology/eapi/vri/1-519107352).

Для локальной проверки сформированы два пакета из 25 синтетических записей. Файл без наклеек валиден по оригиналу 2020 года и получает 25 ошибок отсутствующей наклейки по 2022. Файл с 25 синтетическими наклейками валиден по оригиналу 2022. Оба файла перечитаны и сверены по составу. Примеры находятся в папке `release\Проверочные XML 1.3.0` и предназначены только для локальной проверки.

С версии 1.3.1 тот же проверочный формат доступен для загруженных протоколов в меню настроек. Схема 2020 допускает отсутствие `stickerNum` и требует владельца. Проверки оборудования, реквизитов и измерений применяются в обеих ветвях. Проверочный файл хранится отдельно, распознаётся просмотрщиком по комментарию и фиксируется в аудите отдельно от рабочих выгрузок. Поддержка действующим кабинетом остаётся неподтверждённой.
