## Правила, применяемые в программе

- Поиск начинается автоматически после чтения протокола. При сетевой ошибке его можно запустить снова кнопкой «Повторить поиск». Из Excel используются столбцы «Оборудование» A:D. Столбец E помогает найти выбранную позицию. Файлы Excel, измерения и сведения о поверяемой партии в реестр не передаются.
- Обычное СИ проверяется по точному номеру типа в MIT и паре тип / заводской номер в VRI. Запрос передаёт `verification_date_end`, чтобы проверить прошлые годы. Действие определяется по последней опубликованной поверке не позднее даты протокола. Более новая отрицательная поверка исключает более старую положительную. Сравнивается обозначение модели.
- СИ-эталон ищется по полному номеру MIETA либо по точной паре тип / заводской номер. Тип сверяется с MIT. По `cresults[].vri_id` программа сверяет категорию, регномер, модель, заводской номер и сведения о пригодности и сроке в детальном VRI (`miInfo.etaMI`, `vriInfo`). Несколько карточек одного заводского номера показываются со схемами и сроками. Если полный номер с латинской P отсутствует, вариант с кириллической Р показывается для подтверждения.
- Выбор ответственного сохраняется в SQLite и повторно используется после проверки той же публичной карточки. При недоступности API допустимо сохранённое локальное подтверждение, покрывающее дату поверки. Явное расхождение или истёкший срок из полученного ответа блокируют экспорт. Категории без поддерживаемого запроса продолжают работать через локальный справочник.
- Публичный GET подтверждает наличие и параметры карточки. Равенство всех публичных списков спискам личного кабинета и успешный импорт пакета кабинетом требуют отдельной рабочей проверки.

## Контрольный протокол в 1.3.0

Проверены восемь позиций на 22.11.2026. Подтверждены Ф4101, DT-9939, две карточки ПТСВ-1-2, АСПТ и две карточки ЭЛЕМЕР. Для ИВТМ-7М-Д № 85789 действие последней поверки закончилось 16.11.2026. Для АСПТ в структурированном поле указан точный номер `19973.06.4Р.01149311`. Латинская `P` сохранилась только в строке отображения, поэтому в запрос ушёл кириллический номер без запроса подтверждения. Обе записи ПТСВ и обе записи ЭЛЕМЕР проверены индивидуально, по полным исходным номерам.

Для поверяемого типа 56560-14 MIT подтверждает семейства ТСП и ТСМ. В карточке отдельно приведены правила обозначения исполнения, Ex и длины, а также разные МПИ для вариантов типа. Это позволяет применить согласованное правило модификации к структурированным данным. МПИ в карточке сам по себе не задаёт дату окончания конкретной поверки. [Карточка типа 56560-14](https://fgis.gost.ru/fundmetrology/eapi/mit/d81bf7b7-93bf-1c5a-cba1-3f9599ea73a3).

## Сбой HTTPS в Windows-сборке 1.1.0

Журнал 1.1.0 на компьютере пользователя показал `FileNotFoundError` почти сразу для всех запросов MIT и MIETA. Ошибка воспроизвелась в отдельной сборке PyInstaller с прежним клиентом `urllib`. Исключение возникало в `ssl.SSLContext.__new__` при создании HTTPS-контекста, ещё до выполнения запроса. Точное имя отсутствующего файла стек не показал.

На этом же компьютере `curl.exe` со Schannel и Python вне сборки с OpenSSL 3.5.8 получили HTTP 200 по одним и тем же URL. DNS возвращал IPv4-адреса `212.164.138.14` и `212.164.138.19`. Для обоих адресов Windows выбрала маршрут `208.0.0.0/4` через v2RayTun. Системный WinHTTP показывал прямое соединение, пользовательский прокси и PAC не были настроены. [Проверка сертификатов в curl](https://curl.se/docs/sslcerts.html).

В Windows выпуск 1.2.0 использует WinHTTP с системным хранилищем доверенных сертификатов и автоматическим выбором прокси Windows. Фазы соединения имеют отдельные тайм-ауты. При HTTP 429 и 5xx выполняются ограниченные повторы с учётом короткого числового `Retry-After`. Журнал содержит тип исключения, код Windows или HTTP, причину и длительность. В интерфейсе «Настройки → Проверить подключение» каждый реестр проверяется отдельно. [Режим прокси WinHTTP](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpopen) · [Тайм-ауты WinHTTP](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpsettimeouts).
