## Правила, применяемые в программе

- Поиск начинается автоматически после чтения протокола и повторяется по «Проверить данные». Из Excel используются столбцы «Оборудование» A:D. Строка E помогает найти выбранную позицию, а в запросах используются только структурированные идентификаторы. Файлы Excel, измерения и сведения о поверяемой партии в реестр не передаются.
- Обычное СИ проверяется по точному номеру типа в MIT и паре тип / заводской номер в VRI. Запрос передаёт `verification_date_end`, чтобы проверить прошлые годы. Действие определяется по последней опубликованной поверке не позднее даты протокола. Более новая отрицательная поверка исключает более старую положительную. Сравнивается обозначение модели.
- СИ-эталон ищется по полному номеру MIETA либо по точной паре тип / заводской номер. У карточки сверяются точные реквизиты, пригодность и интервал связанной поверки. Два подходящих эталона с одним заводским номером показываются в окне оборудования со схемами и сроками. Если полный номер с латинской P отсутствует, вариант с кириллической Р показывается для подтверждения.
- Выбор ответственного сохраняется в SQLite и повторно используется после проверки той же публичной карточки. При недоступности API допустимо сохранённое локальное подтверждение, покрывающее дату поверки. Явное расхождение или истёкший срок из полученного ответа блокируют экспорт. Категории без поддерживаемого запроса продолжают работать через локальный справочник.
- Публичный GET подтверждает наличие и параметры карточки. Равенство всех публичных списков спискам личного кабинета и успешный импорт пакета кабинетом требуют отдельной рабочей проверки.
