# Вопросы перед рабочей загрузкой

## Критические

1. Как оператор принимает пакетные сведения о пригодном СИ без наклейки? Публичная справка публикует XSD 2022 с обязательным `stickerNum`. Для этого исключения нужно официальное разъяснение или подтверждение приёма на разрешённом тестовом контуре. [Сравнение схем](schema_discrepancies.md).
2. Где фиксируются окончательное заключение по каждому СИ, причины при смешанном результате и проверка обоих ЧЭ? Для каких двухэлементных модификаций оформляется одна запись?
3. Какие официальные обозначения и алфавиты утверждены для исполнений, включая `AL/DS`, `РЭД`, `Ex` и варианты `М/M`? Нужны описания типов и подтверждённые исключения.
4. Какие точные записи ФИФ ОЕИ выбираются для каждого фактически использованного средства, особенно при двух номерах эталона на единицу и различии `P/Р`? Какими сведениями подтверждается действие на дату поверки?
5. Каким документом подтверждаются шифр, вид поверки при пустой B1, калибровка, дата окончания, владелец, нанесение знаков и наклейка по каждому СИ?
6. Как различать составные номера с одним дефисом и длинные префиксные диапазоны? Нужен утверждённый список или индивидуальная сверка.

## Дополнительные

- Сверить 5–10 завершённых реальных протоколов после разрешения, включая отрицательный и двухэлементный варианты. Подтвердить правила использования поля «Прочие сведения» для поиска по номеру протокола в кабинете.
- Сверить точную карточку средства лаборатории в публичном реестре и кабинете. MIT, MIETA и VRI подтвердили точные публичные карточки, включая две схемы для одного эталона. Эквивалентность всем спискам кабинета требует отдельной рабочей проверки. Пункт 3.4.7 руководства относится к отдельному API с токеном. [Диагностика публичных API](public_registry_diagnostics.md).
