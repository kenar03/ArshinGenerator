Сборки Windows x64 созданы на Windows 11 (10.0.22631) с Python 3.12.14, PySide6 Essentials 6.8.3, PyInstaller 6.13.0 и Inno Setup 6.7.3. Файлы не имеют подписи Authenticode. ## Выполнено

- 31 автоматический тест. Покрыты выбор и сохранение двух схем одного эталона, экспорт обеих схем, повторное использование подтверждений после появления поверки на другой период, проверка связанной карточки VRI, отрицательная поверка, истечение срока, недоступность сети, пагинация и повторы. Проверены 25 автоматических заключений, единое подтверждение знаков для партии, открытие карточки результата и выгрузка кнопкой приложения. Сохранены тесты двух ЧЭ, блока 63, истории, XSD и чтения сохранённого XML.
- При коэффициентах Qt 1,25 и 1,50 с Windows-бэкендом проверены главное окно, окно исправления, таблица выбора двух схем и предварительный просмотр. Все колонки в этих окнах помещаются при проверенном размере экрана.
- Обе сборки запустились с обычным Windows-бэкендом Qt, при PATH из системных каталогов и заведомо отсутствующих внешних путях Python. В каждой образец дал 25 карточек. Статус готовности определяется обычными проверками и отсутствующими подтверждениями.
- Portable запущена из распакованного ZIP. После перемещения в другой каталог с кириллицей и пробелами сохранились SQLite и последняя выбранная папка.
- Установщик проверен временной установкой в текущем профиле. Созданы ярлык в меню «Пуск», выбранный ярлык на рабочем столе и запись удаления в HKCU. Запуск приложения сохранил данные в отдельной пользовательской папке, повторный запуск прочитал настройки. После удаления исчезли приложение, ярлыки и запись HKCU. База осталась на месте.
- SHA-256 шаблона, двух заполненных протоколов и журнала совпали с исходными контрольными суммами. Выполнялись публичные GET-запросы к реестру средств поверки.
- Из обеих итоговых сборок на компьютере с активным v2RayTun получен HTTP 200 от MIT, MIETA и VRI. MIT сначала вернул HTTP 429 и ответил HTTP 200 при автоматическом повторе из каждой сборки. На контрольном протоколе 1260-26 отдельно запущен поиск восьми позиций с проверкой детальных связанных поверок. Обнаружен истёкший срок ИВТМ, для одной карточки требуется сверить написание регистрационного номера. [Поля и ответы API](public_registry_diagnostics.md).

Готовый XML проверен на синтетических сценариях. Приём порталом следует подтвердить уполномоченному сотруднику на достоверных данных, включая вопросы по номеру наклейки, окончательному заключению, написанию модификаций и точным соответствиям эталонов.
